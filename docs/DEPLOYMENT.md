# Развёртывание и резервное копирование

## Локальная разработка

Следуйте README: Node 24, PostgreSQL UTF-8, `.env`, `npm ci`, generate → migrate → seed → dev. DATABASE_URL не должен попадать в логи/репозиторий. `init-env.mjs` не перезаписывает файл. Для локального браузера адрес и WEB_ORIGIN должны совпадать (localhost и 127.0.0.1 — разные origin).

## Compose

`docker compose up --build -d` собирает один stage с приложением, запускает PostgreSQL, одноразовый migrate, API и nginx. Веб-порт 8080 привязан к 127.0.0.1. Healthcheck API проверяет SQL SELECT 1. `docker compose exec api npm run db:seed` запускается отдельно на пустой БД. Миграции не требуют seed для работы API.

Compose подготовлен, но в исходном окружении Docker отсутствует, поэтому успешный Docker-запуск не подтверждён. Выполните эту проверку на машине с Docker Desktop до приёмки диплома.

## Production

HTTPS reverse proxy обязателен для Secure cookie. Настройте NODE_ENV=production и DOCKER_WEB_ORIGIN=https://ваш-домен. Храните секреты вне исходников, ограничьте доступ к бэкапам, используйте отдельную роль БД с минимальными правами. По умолчанию сервер не доверяет произвольному X-Forwarded-For. При настройке прокси отдельно настройте и проверьте trust proxy/rate-limit для вашей топологии, а не для всех адресов.

## Резервная копия

В PowerShell из корня проекта:

```powershell
./scripts/backup.ps1
```

Скрипт запускает pg_dump -Fc внутри контейнера, затем docker compose cp переносит бинарный файл без повреждения перенаправлением PowerShell. Каталог backups игнорируется Git. Копируйте бэкапы на независимый защищённый носитель, задайте политику хранения и регулярно проверяйте восстановление.

## Восстановление в новую БД

Не восстанавливайте поверх рабочей базы без согласования. Создайте отдельную пустую базу, скопируйте dump в контейнер, затем выполните `pg_restore --no-owner --exit-on-error -U <user> -d <new_database> /tmp/backup.dump`. Проверьте количество клиентов, суммы счетов/платежей, вход, расписание и миграции. Только после проверки переключайте приложение на восстановленную базу. Команды удаления базы не включены намеренно.

Добавлен также scripts/verify-backup.mjs: он использует pg_dump/pg_restore из PATH или PG_BIN, восстанавливает в новую crm_restore_* БД и сравнивает количества записей и суммы финансов. Исходную базу он не меняет. Попытка запуска в текущем окружении завершилась ENOENT: облегчённый комплект не содержит pg_dump. Успешное восстановление не подтверждено и обязательно перед реальным использованием.
