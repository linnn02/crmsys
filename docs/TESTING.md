## Покрытие unit/API

Возраст в день рождения, пересечение и смежность интервалов, правила пропусков, точность Decimal, отрицательные платежи, неправильный интервал; отсутствие авторизации/CSRF, RBAC; создание/редактирование/дубль ученика, несколько родителей; вместимость; чужая карточка; серия и конфликт, сдвиг всей серии на неделю; выдача абонемента/счёта; одно списание при повторном запросе, восстановление при изменении отметки; отказ чужому преподавателю; частичная оплата, идемпотентность, возврат и долг; аналитика против БД и исключение финансов; архив с сохранением оплат; снимок цены; отмена занятия с восстановлением; PDF; дедупликация/принадлежность уведомлений; подмена teacherId в фильтре.

## Покрытие E2E

## Воспроизведение

`npm test` создаёт новую базу crm_test_<timestamp>, применяет миграции, запускает seed и Vitest. Он не удаляет существующие базы; диагностические тестовые базы остаются на сервере. Нужны DATABASE_URL, SEED_PASSWORD и CREATEDB. Прямой запуск integration suite без TEST_DATABASE_URL блокируется.

`npm run test:e2e` использует локальные API/Vite (либо запускает их). Перед тестом дождитесь окончания правок и перезапусков dev-server. E2E создают вымышленных представителей в выбранном локальном окружении, поэтому production для них запрещён.

## Найденные и исправленные проблемы

- Несовместимость TypeScript 7 с typescript-eslint: выбрана совместимая стабильная ветка 5.9.3.
- FullCalendar 7 перенёс плагины и CSS в подпути React-пакета: зависимости и импорты исправлены.
- Немедленные exclusion constraints мешали перемещению всей серии на неделю: четвёртая миграция делает проверку отложенной до commit, добавлена реальная проверка переноса.
- Изменяющие действия в диалоге календаря не должны отправлять форму второй раз: отмена занятия явно type=button.
- E2E локаторы адаптированы к доступным ролям FullCalendar 7; тесты ждут завершения входа.
- Прогон во время hot reload был неуспешен; повтор на неизменяемом коде прошёл. Сбой не скрыт ретраями тестов.

## Не проверено

Нагрузочные гонки с большим числом соединений, длительная работа, восстановление на другом сервере, Docker Desktop и production HTTPS. PDF проверен по ответу/сигнатуре и встраиваемому кириллическому шрифту; отдельная визуальная проверка печатной квитанции пока не выполнена. Это ограничения проверки, а не подтверждённые дефекты.
