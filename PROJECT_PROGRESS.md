## Расширение под Oi-Qaragai

Добавлены `Activity`, `Venue`, `InventoryItem`, `ParentConsent`, `ActivityBooking`, `InventoryIssue`, проверки допуска по возрасту/росту/весу, конфликтов бронирований и новые роли курортной команды. Seed создаёт вымышленные программы и будущие бронирования. Подробности: `docs/OIQARAGAI.md`.

## Продолжение Ugusha

Добавлена миграция `202611270001_ugusha_rental_fields`: размер ноги и уровень катания ребёнка, признаки собственного снаряжения и расширенный жизненный цикл брони. Добавлен публичный контракт `POST /api/public/activity-bookings` для будущего сайта/виджета; он создаёт или находит вымышленного гостя, фиксирует согласие и не требует входа в админку. Автоматические проверки API ещё требуют запущенного PostgreSQL.

## Локальный этап онлайн-записи

Добавлен локальный `GET /api/public/activity-slots` с фильтром по дате/возрасту и расчётом занятости, экран `/online-booking`, выбор свободного слота и признаки экипировки. Создание гостя, ребёнка, согласия и брони объединено в одну транзакцию. Добавлена проверка допустимых переходов статуса брони и unit-тест. Внешний сайт, виджет и касса не подключались.

Последняя локальная проверка: `npm run typecheck`, `npm run lint`, `npm run build` и `npx vitest run tests/domain.test.ts` (7 тестов) прошли. Полный `npm test` заблокирован отсутствием PostgreSQL на `localhost:5432`; E2E после исправления схемы формы не завершён из-за той же локальной инфраструктуры.

## Окружение

Node 24.19.0, npm 11.17.0. Локальный PostgreSQL 18.4 запущен из отдельного игнорируемого E:/dev/diplom/.local-postgres, подключён через Prisma. Все четыре миграции применены. Seed проверен на пустых БД: 8 пользователей (1/2/5 по ролям), 50 учеников, 40 родителей, 8 групп, 6 направлений, 3 кабинета, 48 занятий, 50 абонементов и счетов, 34 платежа. В локальной демонстрационной БД также остались синтетические записи первого API/E2E прогона; ничего не удалялось. Последующие API-прогоны выполняются в новых изолированных crm_test_* БД.

Приложение: http://localhost:5173. API: http://localhost:4000. Случайные локальные секреты — только в игнорируемом .env. Пароль seed не публикуется в документации.

Docker отсутствует. В облегчённом локальном комплекте нет pg_dump/pg_restore: запуск scripts/verify-backup.mjs завершился ENOENT до создания резервной копии. Нельзя считать Docker и восстановление проверенными.

## Решения

Модульный монолит, REST, PostgreSQL как единственный источник бизнес-данных. ADMIN/MANAGER/TEACHER. UTC timestamptz, календарь Asia/Almaty. Финансы Decimal(14,2), корректировки отдельными операциями. Исторические связи Restrict, архивирование вместо удаления.

## Оставшиеся работы для полного исходного ТЗ

1. Проверить Docker Compose на машине с Docker и восстановление бэкапа с полными PostgreSQL client tools. Это блокирует полную приёмку.
2. Дополнить отдельные карточки преподавателя/группы и исторические отчёты посещаемости по преподавателям. Сейчас группы/ученики видны в списках, календарь фильтруется, история ученика доступна.
3. Добавить абонемент только на направление без группы; текущая выдача привязана к группе. Отмена занятия всегда восстанавливает списания (chargeCancelled=false); платная отмена не реализована. Исправление ошибочного списания доступно через изменение отметки/отмену занятия, отдельного интерфейса корректировки Usage нет.
4. Реализовать самостоятельные корректируемые счета и расширить распределение одного платежа на несколько счетов при необходимости. Сейчас счёт создаётся при выдаче абонемента, каждый платёж относится к одному счёту, несколько платежей на счёт поддерживаются.
5. Доработать экспорт аналитики и агрегирование платежей по месяцам, точную детализацию посещаемости по группам/преподавателям. Текущие графики и показатели DB-based, экспорт CSV относится к платежам.
6. Полностью описать response-схемы и специализированные request-схемы OpenAPI, унифицировать сортировку/пагинацию всех специализированных ресурсов и добавить серверный поиск в select для справочников >100 записей.
7. Завершить вынос всех строк в i18n-словарь (точка расширения есть, казахского перевода нет), добавить интерфейс изменения названия центра (API готов).
8. Провести нагрузочные, конкурентные и эксплуатационные проверки на целевой инфраструктуре. Локальный rate limit хранится в памяти одного процесса; фонового планировщика уведомлений нет (напоминания материализуются при открытии центра уведомлений).

## Продолжение

Не запускать seed поверх существующих данных и не удалять .env. Начать с чтения этого файла, README и docs/TESTING.md. При новых изменениях схемы добавлять миграцию, не редактировать применённые. Сначала закрыть непроверенное развёртывание и оставшиеся доменные сценарии; не считать MVP полным выполнением расширенного ТЗ.
